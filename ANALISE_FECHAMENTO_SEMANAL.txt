SUMÁRIO EXECUTIVO
=================
O sistema de fechamento semanal é um módulo crítico da aplicação Pastel24h que
processa dados de turnos trabalhados, calcula folha de pagamento, gerencia 
consumos internos e gera relatórios detalhados para gestão financeira do 
restaurante. Este documento apresenta uma análise técnica completa de todos
os componentes envolvidos.

================================================================================
PARTE 1: ARQUITETURA GERAL DO SISTEMA
================================================================================

1.1 FLUXO DE DADOS PRINCIPAL
-----------------------------
1. Frontend solicita cálculo de fechamento semanal
2. Backend coleta dados de múltiplas tabelas (shifts, users, transportModes, etc)
3. Processa horas trabalhadas, consumos e colaborações
4. Calcula valores de pagamento com base em configurações
5. Retorna dados processados para o frontend
6. Frontend permite ajustes manuais
7. Dados finais são persistidos na tabela weekly_reports

1.2 COMPONENTES PRINCIPAIS
---------------------------
Backend:
- /server/routes.ts - Endpoints da API
- /server/storage.ts - Camada de persistência
- /server/collaborator-consumption-service.ts - Gestão de consumos

Frontend:
- /client/src/pages/weekly-report.tsx - Interface principal
- /client/src/lib/calculations.ts - Lógica de cálculos

Banco de Dados:
- Tabela weekly_reports - Armazena relatórios processados
- Tabela shifts - Dados dos turnos
- Tabela shift_collaborators - Colaboradores por turno
- Tabela shift_records - Produtos vendidos/consumidos

---------------------------------------------------------------
Função: Calcular dados automáticos para fechamento semanal
Este é o endpoint mais complexo e crítico do sistema.

Parâmetros de entrada:
  - weekStart: Data início da semana (ISO string)
  - weekEnd: Data fim da semana (ISO string)
  - hourlyRate: Valor da hora trabalhada (número)
  - foodBenefit: Vale alimentação diário (número)
  - consumptionDiscount: Percentual de desconto no consumo interno (0-100)
  - transportRates: Objeto com tarifas de transporte {bus, van, app}
  - reportId: ID do relatório existente (opcional)

LÓGICA DETALHADA DO CÁLCULO:

Passo 1: Buscar todos os funcionários (Linhas 1512-1524)
  - Query JOIN entre users e transportModes
  - Filtra apenas role='employee'
  - Mapeia dados incluindo tipo e preço de transporte

Passo 2: Buscar turnos do período (Linha 1526)
  - Usa storage.getShiftsByDateRange(startDate, endDate)
  - Retorna todos os turnos fechados no período

Passo 3: Para cada funcionário, calcular (Linhas 1530-1795):

  a) Turnos como responsável principal (Linhas 1531-1534)
     - Filtra shifts onde userId = employee.id
     - Apenas turnos com endTime (fechados)

  b) Colaborações em outros turnos (Linhas 1537-1560)
     - Busca na tabela shift_collaborators
     - Calcula horas trabalhadas por diferença de timestamps
     - Soma total de horas como colaborador

  c) Total de horas trabalhadas (Linha 1562)
     - Soma horas como responsável + horas como colaborador

  d) Dias únicos trabalhados (Linhas 1565-1579)
     - Cria Set com datas únicas de trabalho
     - Considera tanto turnos próprios quanto colaborações

  e) Cálculo de transporte (Linhas 1582-1591)
     - Se reportId fornecido, busca dados salvos
     - Senão: dias_trabalhados × tarifa_diária_transporte
     - Usa tipo de transporte configurado no usuário

  f) Vale alimentação (Linhas 1594-1603)
     - Se reportId fornecido, busca dados salvos
     - Senão: dias_trabalhados × valor_benefício

  g) Consumo interno de produtos (Linhas 1606-1753)
     PROCESSO COMPLEXO DE CÁLCULO DE CONSUMO:
     
     - Para cada turno do funcionário:
       1. Busca shift_records do turno
       2. Para cada record com consumed > 0:
          - Busca dados do produto
          - Verifica se é água (gratuita)
          - Calcula: valor_consumo = consumed × price
          - Adiciona aos totais por categoria
     
     - Categorização de consumo:
       * Bebidas: produtos com categoria 'bebidas'
       * Pastéis: produtos com categoria 'pasteis'
       * Água: produtos com nome 'água' (gratuito)
     
     - Fórmula final consumo:
       consumo_total = bebidas + pasteis
       consumo_com_desconto = consumo_total × (1 - desconto/100)

  h) Bônus e deduções (Linhas 1756-1765)
     - Se reportId fornecido, busca valores salvos
     - Senão: inicializa com 0

  i) Cálculo do total a receber (Linhas 1768-1778)
     FÓRMULA PRINCIPAL:
     total = (horas × valor_hora) + transporte + alimentacao + bonus - consumo_com_desconto - deducao

Passo 4: Retornar dados processados (Linhas 1780-1794)
  - Array com objetos EmployeeData contendo todos os cálculos
  - Inclui detalhes de consumo para auditoria

FUNÇÃO AUXILIAR: isWaterProduct (Linhas 1494-1502)
----------------------------------------------------
Verifica se um produto é água (gratuito para funcionários)
Regras:
  - Nome exatamente 'água' ou 'agua'
  - Nome 'água mineral' ou 'agua mineral'
  - NÃO inclui 'água com gás' (pago)

FUNÇÃO: calculatePayroll (Linhas 37-53)
----------------------------------------
Calcula salário total do funcionário

Parâmetros:
  - hours: Horas trabalhadas
  - hourlyRate: Valor por hora
  - transport: Valor transporte
  - food: Vale alimentação
  - consumption: Consumo interno total
  - consumptionDiscount: % desconto (0-100)
  - bonus: Bônus adicional
  - deduction: Dedução adicional

Fórmula detalhada:
  1. hoursPay = hours × hourlyRate
  2. consumptionDiscountAmount = consumption × (consumptionDiscount/100)
  3. finalConsumption = consumption - consumptionDiscountAmount
  4. total = hoursPay + transport + food + bonus - finalConsumption - deduction

IMPORTANTE: O desconto é aplicado SOBRE o consumo, reduzindo o valor descontado

FUNÇÃO: calculateTransportCost (Linhas 68-76)
----------------------------------------------
Calcula custo total de transporte

Parâmetros:
  - daysWorked: Dias trabalhados
  - transportType: Tipo (bus, van, app)
  - rates: Objeto com tarifas

Fórmula:
  custo = dias_trabalhados × tarifa_diária

--------------------------
1. Frontend envia POST para /api/admin/weekly-report/calculate
2. Backend busca todos os funcionários ativos
3. Para cada funcionário:
   a) Identifica turnos como responsável

PARTE 6: REGRAS DE NEGÓCIO CRÍTICAS
================================================================================

6.1 CÁLCULO DE HORAS
---------------------
- Turnos próprios: endTime - startTime (em horas)
- Colaborações: endTime - startTime da shift_collaborators
- Total: soma de ambos
- Precisão: 2 casas decimais

6.2 DIAS TRABALHADOS
---------------------
- Conta dias ÚNICOS, não turnos
- Funcionário pode ter múltiplos turnos no mesmo dia
- Conta apenas UMA vez por dia
- Usado para transporte e alimentação

6.3 CONSUMO INTERNO
--------------------
Regras especiais:
1. Água mineral é GRATUITA (não cobra)
2. Água com gás é PAGA (cobra normal)
3. Desconto padrão: 50% sobre consumo
4. Fórmula: consumed × price × (1 - discount/100)
5. Separa por categoria para relatório

6.4 TRANSPORTE
---------------
- Baseado em dias trabalhados, NÃO em turnos
- Usa configuração individual do funcionário
- Tarifa é ida e volta (round trip)
- Tipos: bus, van, app (extensível)

6.5 VALE ALIMENTAÇÃO
---------------------
- Valor fixo por dia trabalhado
- Não depende de horas
- Configurável globalmente

6.6 FÓRMULA FINAL
-----------------
TOTAL = (horas × valor_hora) + transporte + alimentação + bônus - consumo_com_desconto - dedução

Onde:
- consumo_com_desconto = consumo_total × (1 - desconto_percentual/100)
- transporte = dias_trabalhados × tarifa_transporte
- alimentação = dias_trabalhados × valor_benefício
