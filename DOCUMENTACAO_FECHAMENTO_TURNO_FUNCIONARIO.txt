1. VISÃO GERAL DO SISTEMA
================================================================================

O sistema de fechamento de turno é um processo robusto e detalhado que permite
aos funcionários registrar todas as transações financeiras e contabilizar
corretamente o caixa ao final do expediente. O processo é dividido em várias
etapas sequenciais para garantir precisão e transparência.

COMPONENTES PRINCIPAIS:
- CashRegister: Registro de pagamentos e contagem de caixa durante o turno
- CloseShiftModal: Modal de fechamento com validações e cálculos
- shift-processor.ts: Backend que processa dados do turno com correções
- Sistema de divergências: Detecção automática de inconsistências

function calculateCashDivergence(
  finalCash: number,      // Dinheiro contado fisicamente
  initialCash: number,    // Dinheiro inicial do turno
  cashSales: number       // Vendas em dinheiro registradas

  const expectedCash = initialCash + cashSales;

```typescript
/**
 * Fórmula principal do inventário:
 * Quantidade Vendida = Entrada + Chegada - Sobra - Descarte - Consumo Interno
 */
export function calculateSold(
  entry: number,      // Quantidade inicial
  arrival: number,    // Chegadas durante o turno
  leftover: number,   // Sobras contadas
  discard: number,    // Descartes registrados
  consumed: number    // Consumo interno
): number {
  return Math.max(0, entry + arrival - leftover - discard - consumed);
}

// Exemplo prático:
// Pastéis Comuns: 50 inicial + 20 chegaram - 8 sobraram - 2 descartados - 3 consumo = 57 vendidos
const vendidos = calculateSold(50, 20, 8, 2, 3); // = 57
```

```typescript
// Divergência considerando todas as variáveis:
function calculateFullDivergence(shift) {
  const initialCash = parseFloat(shift.initialCash || '0');
  const initialCoins = parseFloat(shift.initialCoins || '0');
  const cashSales = parseFloat(shift.payments?.cash || '0');
  const finalCash = parseFloat(shift.finalCash || '0');
  const finalCoins = parseFloat(shift.finalCoins || '0');

  // Calcular retiradas administrativas
  const totalWithdrawals = shift.cashAdjustments?.reduce((sum, adj) => {
    return sum + parseFloat(adj.amount || '0');
  }, 0) || 0;

  // Dinheiro esperado = inicial + vendas - retiradas
  const expectedCash = initialCash + cashSales - totalWithdrawals;
  const expectedTotal = expectedCash + initialCoins; // Moedas não mudam

  // Total contado físicamente
  const countedTotal = finalCash + finalCoins;

  // Divergência final
  return countedTotal - expectedTotal;
}
```

// Exemplo de processamento completo (simplificado):
app.post("/api/shifts/close", async (req, res) => {
  try {
    const { shiftId, payments, countedFinalCash, countedFinalCoins, notes } = req.body;

    // 1. Buscar turno atual
    const shift = await storage.getShift(shiftId);

    // 2. Calcular divergência
    const expectedCash = parseFloat(shift.initialCash) + parseFloat(payments.cash);
    const countedTotal = parseFloat(countedFinalCash) + parseFloat(countedFinalCoins);
    const divergence = countedTotal - (expectedCash + parseFloat(shift.initialCoins));

    // 3. Validar se divergência exige justificativa
    if (Math.abs(divergence) > MAX_CASH_DIVERGENCE && !notes) {
      return res.status(422).json({
        message: "Divergência detectada - observação obrigatória",
        details: { cashDivergence: divergence, requiresNotes: true }
      });
    }

    // 4. Processar fechamento
    const closedShift = await storage.closeShift({
      shiftId,
      finalCash: countedFinalCash,
      finalCoins: countedFinalCoins,
      cashDivergence: divergence,
      notes,
      // Cálculos para próximo turno...
    });

    // 5. Notificar clientes WebSocket
    notifyShiftClients(shiftId, { type: 'SHIFT_CLOSED', payload: closedShift });

    res.json(closedShift);
  } catch (error) {
    // Tratamento robusto de erros...
  }
});

================================================================================

PROBLEMA: "DIVERGÊNCIA MUITO ALTA"
----------------------------------------------------------------

**Possíveis causas:**
- Erro na contagem física do dinheiro
- Venda registrada incorretamente
- Troco dado errado para cliente
- Problema com maquininha de cartão

**Como resolver:**
1. Conte o dinheiro novamente com calma
2. Revise os pagamentos registrados
3. Confira se total das maquininhas está correto
4. Se persistir, justifique detalhadamente

PROBLEMA: "INCONSISTÊNCIA DE VENDAS"
----------------------------------------------------------------

**Possíveis causas:**
- Produto vendido mas não registrado
- Registro duplo de venda
- Preço informado incorreto
- Erro na quantidade de produtos

**Como resolver:**
1. Confira lista de produtos vendidos
2. Compare com total de pagamentos
3. Procure vendas que podem ter sido esquecidas
4. Justifique se não conseguir identificar

PROBLEMA: "SISTEMA NÃO ACEITA FECHAMENTO"
----------------------------------------------------------------

**Possíveis causas:**
- Campos obrigatórios não preenchidos
- Divergência sem justificativa
- Valores negativos ou inválidos
- Problemas de conexão

**Como resolver:**
1. Verifique se todos os campos estão preenchidos
2. Preencha observações se há divergência
3. Confira se valores estão corretos (sem símbolos)
4. Tente novamente ou chame administrador

PROBLEMA: "MAQUININHA MOSTRA VALOR DIFERENTE"
----------------------------------------------------------------

**Situação comum:**
- Sistema pede valor total da maquininha
- Funcionário confunde com valor do turno atual

**Solução:**
- Informe o valor TOTAL mostrado na maquininha
- Sistema calcula automaticamente quanto foi vendido no turno
- Não tente calcular manualmente
